# Recipe Service — REST API

Бэкенд сервиса для обмена рецептами и кулинарных блогов.
ЛР1: реализация REST API на основе технического дизайна из ДЗ1 и ДЗ2.

## Стек

- Node.js + TypeScript
- Express — веб-фреймворк
- TypeORM — ORM
- SQLite (better-sqlite3) — база данных (файл на диске, без установки СУБД)
- JWT (jsonwebtoken) — авторизация
- bcryptjs — хэширование паролей
- swagger-ui-express — документация API

## Установка и запуск

```bash
npm install
cp .env.example .env      # при желании поменять секреты/порт
npm run seed               # один раз: наполняет категории, теги, единицы измерения и тестового админа
npm run dev                 # запуск в режиме разработки (автоперезапуск при изменениях)
```

После запуска:
- API: `http://localhost:3000/api`
- Swagger UI: `http://localhost:3000/api-docs`

Тестовый администратор (создаётся скриптом `npm run seed`):
```
email: admin@recipes.local
password: admin12345
```

## Эндпоинты

### Auth
- `POST /auth/register` — регистрация
- `POST /auth/login` — вход, возвращает JWT
- `POST /auth/verify-email` — подтверждение email по токену

### Users (требуют авторизации)
- `GET /users/me` — профиль текущего пользователя
- `PUT /users/me` — обновить профиль
- `GET /users/me/recipes` — свои рецепты (в любом статусе)
- `GET /users/me/favorites` — избранные рецепты

### Recipes
- `GET /recipes` — список опубликованных рецептов (фильтры: `search`,
  `categoryId`, `difficulty`, `cookingTime`, `tagId`; сортировка: `sortBy`
  (`difficulty`/`popularity`), `order`; пагинация: `page`, `limit`)
- `GET /recipes/{id}` — рецепт по ID
- `POST /recipes` 🔒 — создать рецепт (статус `draft`)
- `PUT /recipes/{id}` 🔒 — обновить (только автор)
- `DELETE /recipes/{id}` 🔒 — удалить (автор или админ)
- `POST /recipes/{id}/submit` 🔒 — отправить на модерацию
- `POST` / `DELETE /recipes/{id}/like` 🔒 — лайк / убрать лайк
- `POST` / `DELETE /recipes/{id}/favorite` 🔒 — избранное / убрать из избранного

### Admin (требуют роль admin)
- `PUT /admin/recipes/{id}/approve` — одобрить рецепт
- `PUT /admin/recipes/{id}/reject` — отклонить рецепт
- `DELETE /admin/recipes/{id}` — удалить любой рецепт
- `DELETE /admin/comments/{id}` — удалить любой комментарий

### Comments
- `GET /comments/recipe/{recipeId}` — список комментариев
- `POST /comments/recipe/{recipeId}` 🔒 — добавить комментарий
- `DELETE /comments/{id}` 🔒 — удалить (автор или админ)

### Справочники
- `GET /ingredients?search=` — поиск по ингредиентам
- `GET /units` — единицы измерения

🔒 — требуется заголовок `Authorization: Bearer <token>`

## Технические решения

Зафиксированы решения по неоднозначным местам ТЗ (main.tsp):

1. **Статусы рецепта**: `draft` → `pending` (после `/submit`) → `published`/`rejected`
   (решение админа). Из `rejected` можно отправить на модерацию повторно.
2. **`GET /recipes`** возвращает только `published`. **`GET /recipes/{id}`**
   доступен всем, если `published`; иначе — только автору или админу (иначе 404,
   чтобы не палить существование чужого черновика).
3. **`PUT /recipes/{id}`** — редактирует только автор (админ модерирует через
   отдельные `/admin/recipes/{id}/approve|reject`, а не через PUT).
4. **`cookingTime`-фильтр** трактуется как "не более N минут" (`<=`).
5. **Лайк/избранное** — раздельные `POST`/`DELETE` (не тоггл). Повторный лайк
   → 409, снятие несуществующего лайка → 404.
6. **Подтверждение email** — реальная отправка писем не делается (нет
   почтового сервиса в стеке курса). Токен подтверждения выводится в консоль
   сервера при регистрации. Вход в систему подтверждение email не блокирует.
7. **Категории/теги/единицы измерения** — отдельных CRUD-эндпоинтов для них
   в API нет (см. `main.tsp`), поэтому они заполняются один раз через
   `npm run seed`.
8. **`/ingredients`** — поиск ведётся по всем ингредиентам всех рецептов
   (ингредиент не отдельный справочник, а часть рецепта — так задано в схеме).

## Известные ограничения

- Нет автоматических тестов — они появятся отдельным этапом (ДЗ3, Postman).
- Нет Docker и микросервисов — по плану курса это более поздние этапы.
- Загрузка файлов не реализована: изображение — просто строка-URL (как решено в ДЗ1).
- Код не был запущен автоматически при разработке (нет доступа к npm registry
  в среде, где писался код) — первый успешный `npm run dev` будет на машине
  автора.
